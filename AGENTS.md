# AGENTS.md

Guidance for AI agents working in this repository.

## Overview

`@lobehub/fluent-emoji` is a small React 19 library (`FluentEmoji` component plus emoji / CDN helpers) that renders Microsoft Fluent Emoji. The images themselves are published as separate asset packages and are loaded at runtime from npmmirror or unpkg. The docs site, built with `@lobehub/docs-kit` (`lobedocs`), is at <https://fluent-emoji.lobehub.com>.

Key paths:

| Path                             | What it is                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `src/index.ts`                   | Public exports: `FluentEmoji`, `getEmoji`, `getEmojiNameByCharacter`, `getFluentEmojiCDN`                          |
| `src/<Name>/index.(ts\|tsx)`     | Implementation; `src/<Name>/index.mdx` is its docs page, `src/<Name>/demos/` its demos                             |
| `src/getFluentEmojiCDN/utils.ts` | Style → asset package mapping, file naming (`emojiToUnicode`), anim package split                                  |
| `packages/*`                     | Asset packages (pnpm workspace): `3d`, `anim1`–`anim4`, `modern`, `flat`, `mono`, private `anim`                   |
| `docs/`                          | Docs home (`home/home.tsx` + `home/*`, frontmatter in `index.mdx`), `changelog.mdx`, `components/` (emoji gallery) |
| `docs.config.ts`                 | `lobedocs` config                                                                                                  |
| `scripts/`                       | One-off asset scripts (see below)                                                                                  |

## Using Skills

The `.agents/skills/` directory contains two skills, the same ones committed in `lobehub/lobe-editor` (`📝 docs: add agent skills for the docs site`):

| Skill                   | Use it when                                                                                                                                                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `using-docs-kit`        | Writing or fixing docs pages (`index.mdx`, `<Demo>`, `<Api>`), editing `docs.config.ts`, or debugging `lobedocs build` failures. Read `SKILL.md` first, then `reference/config.md` / `reference/validations.md` as needed. |
| `building-landing-home` | Redesigning the docs home (`docs/home/home.tsx`) with `@lobehub/ui/awesome` landing components.                                                                                                                            |

To use one, read its `SKILL.md` (e.g. `.agents/skills/using-docs-kit/SKILL.md`) before starting the task. Note that the skills are generic to LobeHub docs sites: their examples use `pnpm` and other packages; in this repo use `bun` and the paths below. `.agents/` is excluded from remark and prettier (`.remarkignore`, `.prettierignore`) so the skills stay identical to the upstream copies; don't reformat them.

<https://fluent-emoji.lobehub.com/skills.md> and <https://fluent-emoji.lobehub.com/llms.txt> are generated by `lobedocs build` for **downstream consumers** of `@lobehub/fluent-emoji`, not for working on this repo. Keep them correct by keeping `index.mdx` frontmatter and headings accurate.

## Writing Docs

- **Component / util pages**: `src/<Name>/index.mdx` (only files named `index.mdx` under `src/` are picked up, per `atomDirs` in `docs.config.ts`). URL = `/components/<kebab-name>`, e.g. `src/getFluentEmojiCDN/index.mdx` → `/components/get-fluent-emoji-cdn`.
- **Frontmatter** (required): `title` (match the export name), `description` (plain one or two sentences, it feeds SEO, skills.md and llms.txt), `category` (existing values: `Components`, `Utils`).
- **Demos**: `src/<Name>/demos/*.tsx`, one `export default` component, imported in MDX with `?demo` and rendered via `<Demo of={X} />`. Import the library by package name (`import { FluentEmoji } from '@lobehub/fluent-emoji'`); `docs.config.ts` aliases it to `src`. See `src/FluentEmoji/demos/index.tsx` (a `StoryBook` + `useControls` playground from `@lobehub/ui/storybook`, used with `layout="bare"`).
- **API tables**: `<Api name="FluentEmoji" />`; props come from the TypeScript types, so document props with JSDoc in the component (`@default` must match the runtime default in the destructuring, see `src/FluentEmoji/index.tsx`).
- **Headings**: start at `##`; keep them short and stable (they appear in llms.txt).
- **Home / changelog**: `docs/home/home.tsx` (set as `homePage` in `docs.config.ts`) with sections in `docs/home/*` and the emoji gallery in `docs/components/*`; `docs/index.mdx` holds its frontmatter. `docs/changelog.mdx` imports `../CHANGELOG.md` (generated by semantic-release, don't edit by hand).
- **Preview**: `bun run dev` (alias of `docs:dev`, i.e. `lobedocs dev`). Restart it after editing `docs.config.ts`. `bun run docs:build` runs the full build and its validations.
- Code-only snippets in MDX (see `src/getEmojiByCharacter/index.mdx`) are fine for utils without a visual demo.

## Adding New Emoji / Asset Package / Component

**New emoji or updated artwork**

1. There is no script in this repo that downloads assets from upstream ([microsoft/fluentui-emoji](https://github.com/microsoft/fluentui-emoji)); assets were committed directly (see `✨ feat: Add fluent emoji`, `✨ feat: Bump Fluent Emoji`). Put files into the style package's `assets/` folder:
   - `packages/3d/assets/*.webp`, `packages/modern/assets/*.svg`, `packages/flat/assets/*.svg`, `packages/mono/assets/*.svg`
   - animated: `packages/anim/assets/*.webp` (private source folder)
2. File name = the emoji's code points in lowercase hex joined by `-` (`emojiToUnicode` in `src/getFluentEmojiCDN/utils.ts`), e.g. `1f600.webp`, `0023-fe0f-20e3.svg`. A wrong name means a 404 at runtime.
3. Animated assets: run `bun run build:static` (`scripts/groupAnim.ts`). It clears `packages/anim1`–`anim4/assets/*.webp` and copies `packages/anim/assets` into them by code point (`< 1f469` → anim1, `< 1f620` → anim2, `< 1f9a0` → anim3, else anim4). These `*.webp` copies are gitignored in each `anim*` package and are only needed for publishing. The split must stay in sync with `emojiAnimPkg` in `src/getFluentEmojiCDN/utils.ts`.
4. The docs grid and `getEmojiNameByCharacter` take their emoji list and names from the `@lobehub/emojilib` dependency, so a new emoji only appears there if emojilib has it.
5. Asset packages are released separately (`bun run release:static`, multi-semantic-release); that step is commented out in `.github/workflows/release.yml`.

**New asset package**: create `packages/<name>/` with `package.json` (`"files": ["assets"]`, public `publishConfig`, like `packages/flat/package.json`), `README.md` and `assets/`; then add the style to `EmojiType` and `genEmojiUrl` in `src/getFluentEmojiCDN/utils.ts`, and to the `type` options in docs/demos.

**New component or helper**

1. Add `src/<Name>/index.ts(x)`; for client components keep `'use client'` at the top (tsdown runs with `unbundle: true` to preserve it, see `tsdown.config.ts`).
2. Export it from `src/index.ts`.
3. Add `src/<Name>/index.mdx` (+ `demos/` if visual) as described above.
4. Run the checks below.

## Conventions & Checks

Package manager is **bun** (CI runs `bun i`; there is no lockfile by design). If `node_modules` is missing, run `bun install` (it also installs husky hooks via `prepare`).

| Command                 | What it does                                                    |
| ----------------------- | --------------------------------------------------------------- |
| `bun run ci`            | `lint` + `type-check` (what CI runs)                            |
| `bun run lint`          | ESLint with `--fix` on `src` and `packages`                     |
| `bun run type-check`    | `tsc --noEmit`                                                  |
| `bun run lint:circular` | dpdm circular-import check on `src`                             |
| `bun run lint:md`       | remark on Markdown                                              |
| `bun run test`          | Vitest (`--passWithNoTests`; there are currently no test files) |
| `bun run build`         | tsdown → `es/`                                                  |
| `bun run docs:build`    | Build the docs site (with lobedocs validations)                 |

- Pre-commit hook runs `type-check`, `lint:circular` and lint-staged (prettier / remark / eslint / stylelint on staged files); commit-msg runs commitlint.
- Commit messages: gitmoji + conventional commit, lowercase scope if any, e.g. `📝 docs: update README`, `✨ feat: add xxx`, `🐛 fix(cdn): xxx`.
- Never use `--no-verify`; if a hook fails, fix the cause or report it.
- Do not push, force-push, or publish unless explicitly asked. Releases are made by CI (semantic-release).
